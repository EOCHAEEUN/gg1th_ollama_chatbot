# CAPY AI Chat — PRD (Product Requirements Document)

- 문서 버전: 1.0
- 작성일: 2026-09-22
- 대상 프로젝트: `react_basic` (React + FastAPI + Ollama 기반 로컬 LLM 채팅 앱)

## 1. 개요

로컬 환경(Ollama)에서 돌아가는 LLM과 대화하는 웹 채팅 앱. 외부 API 비용 없이
로컬에 설치된 모델로 대화하며, 역할(프리셋)에 따라 답변 스타일을 바꿔볼 수 있다.

### 1.1 배경 / 문제 정의

- 로컬 LLM(Ollama)은 설치되어 있지만 터미널에서 커맨드로 묻고 답하는 방식은
  대화 이력 관리, 파라미터 조정, 코드 하이라이팅 등이 불편하다.
- 프롬프트/temperature 같은 값을 매번 손으로 바꾸는 것도 번거롭다.
- → 브라우저에서 켜서 바로 쓸 수 있는 채팅 UI가 필요하다.

### 1.2 목표

- 로컬 Ollama 모델과 웹 UI로 대화한다.
- 미리 정의된 역할(프리셋)로 답변 성격을 빠르게 바꿀 수 있다.
- 대화를 파일로 저장하고 다시 불러올 수 있다.
- 코드가 포함된 답변을 가독성 있게(코드 블록 + 복사 버튼) 보여준다.

### 1.3 목표가 아닌 것 (Non-goals)

- 다중 사용자/로그인/권한 관리
- 클라우드 LLM(OpenAI 등) 연동
- 대화 내용의 서버 측 영구 저장(현재는 클라이언트 JSON 파일로만 저장)
- 이미지/PDF 업로드, TTS/STT 등 멀티모달 기능 (범위 밖, 향후 별도 기획 시 검토)

## 2. 사용자 및 사용 시나리오

### 2.1 대상 사용자

- 로컬에 Ollama와 모델을 설치해 둔 1인 개발자/학습자 (현재는 단일 사용자 전제)

### 2.2 핵심 시나리오

1. 앱을 켜면 설치된 Ollama 모델 목록을 자동으로 불러온다.
2. 사용자는 프리셋(강사/리뷰어/엔지니어/직접 입력) 중 하나를 골라 답변 성격을 정한다.
3. 메시지를 입력하고 전송하면, 이전 대화 이력과 함께 서버로 전달되어 답변을 받는다.
4. 답변에 코드가 포함되면 코드 블록으로 표시되고, 복사 버튼으로 바로 복사할 수 있다.
5. 대화가 마음에 들면 JSON으로 저장하고, 나중에 다시 불러와 이어볼 수 있다.
6. 대화 도중 프리셋을 바꾸면, 대화가 초기화된다는 확인을 받은 뒤 적용한다.

## 3. 기능 요구사항

### 3.1 모델 연결 및 상태 표시

- 앱 로드 시 `GET /api/models` 호출로 설치된 모델 목록을 조회한다.
- 상태는 4가지로 구분해 사이드바에 표시한다: `불러오는 중` / `준비 완료` / `설치된 모델 없음` / `연결 확인 필요`.
- 모델이 없거나 서버 연결에 실패하면 채팅 영역에도 안내 메시지를 노출한다.
- 모델이 준비되지 않으면 메시지 입력/전송이 비활성화된다.

### 3.2 프리셋(역할) 선택

- 프리셋 3종 제공: **초보자 강사**, **코드 리뷰어**, **현업 엔지니어**. 그 외 **직접 입력**(커스텀) 지원.
- 각 프리셋은 시스템 프롬프트, `temperature`, `top_p`, `num_predict` 값을 한 세트로 갖는다.
- 프리셋 전환 시:
  - 진행 중인 대화가 없으면 즉시 적용.
  - 진행 중인 대화가 있으면 확인 모달을 띄우고, 확인 시에만 프리셋 적용 + 대화 초기화.
- 시스템 프롬프트를 직접 수정하면 프리셋 선택값은 자동으로 `직접 입력`으로 전환된다.

### 3.3 생성 파라미터 조정

- `temperature` (0~2, 0.05 단위), `top_p` (0~1, 0.05 단위), `num_predict` (1~2048) 조정 가능.
- 슬라이더로 실시간 값 확인 가능.

### 3.4 대화(채팅)

- 텍스트 입력 후 Enter로 전송, Shift+Enter로 줄바꿈.
- 전송 시 `POST /api/chat`으로 `message`, `history`, `model`, `system_prompt`,
  `temperature`, `top_p`, `num_predict`를 전달한다.
- 응답 대기 중에는 로딩(타이핑) 인디케이터를 표시한다.
- 요청 실패 시 에러 메시지를 표시하고, 직전에 낙관적으로 추가했던 사용자 메시지는
  롤백하며 입력창에 텍스트를 복원한다.
- 마지막 응답의 소요 시간(초)과 현재까지의 메시지 개수를 하단에 표시한다.
- 대화가 없을 때는 추천 질문 버튼(퀵 프롬프트) 4종을 노출한다.

### 3.5 코드 블록 렌더링

- 답변 속 ` ```언어\n코드``` ` 형식을 파싱해 코드 블록으로 분리 렌더링한다.
- 코드 블록에는 언어명과 "복사" 버튼이 있으며, 복사 성공 시 1.6초간 "복사됨" 표시로 바뀐다.

### 3.6 대화 저장 / 불러오기

- **저장**: 현재 메시지 목록과 설정(모델, 프리셋 ID, 시스템 프롬프트, temperature,
  top_p, num_predict)을 JSON 파일(`capy-ai-chat-YYYY-MM-DD.json`)로 다운로드한다.
- **불러오기**: JSON 파일을 업로드하면 메시지와 설정을 복원한다.
  - `messages` 배열이 아니면 에러 처리.
  - `role`이 `user`/`assistant`가 아니거나 `content`가 문자열이 아닌 메시지는 제외.
  - 저장된 모델/프리셋 값이 현재 목록에 없으면 무시(현재 값 유지).
- **초기화**: 현재 대화와 에러/소요시간 표시를 모두 비운다.

### 3.7 테마

- 라이트/다크 모드를 버튼으로 토글 가능.
- 최초 진입 시 `localStorage`에 저장된 값을 우선 적용하고, 없으면 OS 다크모드 설정을 따른다.
- 변경 사항은 `localStorage`에 저장되어 다음 방문 시에도 유지된다.

## 4. 비기능 요구사항

- **환경**: 로컬 실행 전제 (개발 서버: Vite `/api` → `http://127.0.0.1:8000` 프록시).
- **성능**: 응답 스트리밍은 지원하지 않음(완료된 응답을 한 번에 표시) — 현재 범위.
- **접근성**: 주요 인터랙션 요소에 `aria-label`/`role` 부여(예: 로딩 영역 `aria-live="polite"`).
- **데이터 보존**: 서버 측 영구 저장소 없음. 새로고침 시 대화는 사라지며, 보존하려면
  사용자가 직접 "저장" 기능으로 파일을 내려받아야 한다.

## 6. API 계약 (프론트엔드 기준)

> 백엔드 구현은 이 저장소 범위 밖이며, 아래는 프론트엔드가 기대하는 계약입니다.

### `GET /api/models`

응답:
```json
{ "models": ["llama3.1", "qwen2.5", "..."] }
```

### `POST /api/chat`

요청:
```json
{
  "message": "질문 내용",
  "history": [{ "role": "user" | "assistant", "content": "..." }],
  "model": "llama3.1",
  "system_prompt": "...",
  "temperature": 0.4,
  "top_p": 0.7,
  "num_predict": 700
}
```

응답:
```json
{ "message": "답변 내용", "elapsed_time": 3.2 }
```

실패 시 (HTTP 4xx/5xx):
```json
{ "detail": "에러 메시지" }
```

## 7. 향후 검토 (범위 밖, 백로그)

- 응답 스트리밍(토큰 단위 렌더링)
- 이미지 업로드 + 설명 생성 + TTS 낭독
- PDF 업로드 + 요약
- 서버 측 대화 영구 저장(DB)
- 다중 사용자/세션 관리

## 8. 용어

| 용어 | 의미 |
|---|---|
| 프리셋(Preset) | 시스템 프롬프트 + temperature/top_p/num_predict를 묶어놓은 역할 세트 |
| temperature | 답변의 무작위성/창의성 조절 값 (낮을수록 일관, 높을수록 창의적) |
| top_p | 다음 토큰 후보를 누적 확률로 제한하는 값 |
| num_predict | 응답으로 생성할 최대 토큰 수 |
